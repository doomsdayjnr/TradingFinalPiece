To protect your software, you need to understand two key concepts: **Source Code vs. Executable** and **Compilation Protection**.

When building an Expert Advisor (EA) in MetaTrader 5, there are two distinct file types:

1. **`.mq5` File (Source Code):** This is readable, plain-text code that you or Codex write. Anyone with access to this file can modify parameters, delete licensing logic, or copy the strategy.
2. **`.ex5` File (Executable Binary):** This is the compiled machine-code binary generated by the MetaEditor compiler. **This is what you give to users.** Users drag and drop the `.ex5` file into MetaTrader 5 to run it. They cannot open, view, or edit the underlying code inside an `.ex5` file.

---

### How to Ensure the User Can't Modify or Bypass Your EA

Giving users a compiled `.ex5` file prevents them from seeing the code. To prevent theft or unauthorized sharing (like giving the `.ex5` file to friends who didn't register under your affiliate link), implement **3 levels of protection**:

#### Level 1: MetaEditor Cloud Protector (Decompilation Protection)

Even compiled binaries can theoretically be reversed using expensive third-party decompilers. MetaTrader 5 includes a free built-in tool called **MQL5 Cloud Protector** inside MetaEditor:

* Once your code compiles into an `.ex5` file, you run `Tools` → `MQL5 Cloud Protector`.
* It encrypts the binary with native machine code, rendering decompilation practically impossible.

#### Level 2: Account-Number Locking inside the Code

Inside the EA code (`OnInit` function), Codex can write a hard execution check that compares the current MetaTrader account number running the bot against an authorized account number.

If the account number isn't verified in your system, the EA shuts down instantly.

```mql5
// Built into the compiled .ex5 file (User cannot alter this)
int OnInit()
{
    long currentAccount = AccountInfoInteger(ACCOUNT_LOGIN);
    long authorizedAccount = 12345678; // Dynamically set per user or checked via API

    if (currentAccount != authorizedAccount)
    {
        Alert("Unauthorized Account! Please sign up using our broker partner link.");
        return(INIT_FAILED); // Stops the EA from loading completely
    }
    
    return(INIT_SUCCEEDED);
}

```

#### Level 3: Web-Based Remote API License Verification (Most Secure)

Instead of hardcoding single account numbers into separate `.ex5` files, the EA makes a background HTTPS request to your SaaS server whenever it boots up or trades.

1. The EA captures the user's active **MT5 Account Number**.
2. It sends a request to your web backend: `[https://your-api.com/v1/verify?account_id=12345678](https://your-api.com/v1/verify?account_id=12345678)`.
3. Your web backend checks your database table:
* **If `is_verified == true**` (they signed up under your affiliate link): Server returns `{"status": "allowed"}`.
* **If `is_verified == false**` (or account not found): Server returns `{"status": "denied"}` and the EA disables itself.
